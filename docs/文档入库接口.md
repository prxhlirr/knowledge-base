# 知识库文档（第三方对接）API 文档

## 1. 概述

本文档为第三方业务系统对接知识库提供标准接口指南。目前系统支持两种主流的入库模式：

1. **直接文件流上传（Upload）**：第三方系统按标准的 Multipart 表单式直接推送物理文件流至知识库。
2. **知识库混合检索接口**：第三方系统按照标准检索格式检索知识库中文档信息。
3. **知识库文档下载接口**：第三方系统按照检索出来的文档信息下载源文件。

---

## 2. 接口 1：文件流直传接口

适用于第三方系统已经在本地内存或临时目录中持有文件，直接向知识库推送的场景。

**请求路径**：`POST /api/v1/admin/doc/upload`
**Content-Type**：`multipart/form-data`

### 2.1 请求参数（Form-Data）

| 参数名             | 类型         | 必填                                | 默认值              | 描述                                                                                                                                                 |
|:--------------- |:---------- |:---------------------------------:|:---------------- |:-------------------------------------------------------------------------------------------------------------------------------------------------- |
| `files`         | File Array | **是** | -                | 要上传的文件流数组（支持同批次多文件上传）。                                                                                                                             |
| `tag`           | String     | 否                                 | -                | **【核心路由字段】** 业务标签（如：“法律法规”、“招标公告”）。系统将据此自动把该文档路由至对应的专有分区物理索引中。                                                                                     |
| `visibility`    | String     | 否                                 | `INTERNAL`       | **【权限控制字段】** 文档可见度。<br>可选值：<br>`PUBLIC`: 全网公开（含匿名）<br>`INTERNAL`: 内部全员可见<br>`DEPT`: 指定部门可见（须配合 `deptCode`）<br>`PRIVATE`: 仅自己可见<br>`GRANT`: 指定特定人可见 |
| `deptCode`      | String     | 否                                 | -                | 部门编码。当 `visibility` 为 `DEPT` 时，此项**必填**，否则拒绝入库。                                                                                                    |
| `unit`          | String     | 否                                 | -                | 来源发布单位名称。                                                                                                                                          |
| `docNumber`     | String     | 否                                 | -                | 公文发文字号（如：“京政发〔2026〕1号”）。                                                                                                                           |
| `owner`         | String     | 否                                 | -                | 文档负责人 / 作者。                                                                                                                                        |
| `publishTime`   | String     | 否                                 | -                | 发布时间（格式：`YYYY-MM-DD`）。                                                                                                                             |
| `searchQueries` | String     | 否                                 | -                | 自定义检索增强词/同义词。召回时若命中这些词，将强关联本文件。                                                                                                                    |
| `skipFirstPage` | Boolean    | 否                                 | `false`          | 是否忽略第一页。<br>适用场景：对于带扫描封面的 PDF 文件，设为 `true` 可过滤无效干扰信息。                                                                                              |
| `targetIndex`   | String     | 否                                 | `kb_document_v1` | 不建议传。建议统一传 `tag` 实现智能动态路由。若无 `tag` 则作为底层兜底走该物理索引。                                                                                                  |

### 2.2 请求示例 (cURL)

```bash
curl -X POST "http://<host>/api/v1/admin/doc/upload" \
  -H "Authorization: Bearer <your_token>" \
  -H "X-Search-AppCode: <app_code>" \
  -F "files=@/path/to/local_document.pdf" \
  -F "tag=法律法规" \
  -F "visibility=DEPT" \
  -F "deptCode=D_RD_7788" \
  -F "owner=zhangsan"
```

## 3. 响应参数说明 (公共)

以上两个接口若调用成功，响应体结构完全一样：

```json
{
  "code": 200,
  "msg": "上传文件已进入排队队列",
  "data": "b_1a2b3c4d5e6f7g8h"  // <--- 这个就是批次号（batchId）
}
```

异常情况示例：

```json
{
  "code": 400,
  "msg": "可见度为 DEPT 时，部门编码(deptCode)不能为空"
}
```



## 4. 接口 2：知识库检索接口

适用于第三方系统通过传入文本查询词，直接获取知识库精排后文档检索结果的场景。

**请求路径**：`POST /api/v1/search`
**Content-Type**：`application/json`

### 4.1 请求头 (Headers)

| Header名            | 必填    | 描述                                                     |
|:------------------ |:-----:|:------------------------------------------------------ |
| `X-Search-AppCode` | **是** | 第三方系统专属安全认证码（AppCode），由管理员下发。必须带有合法AppCode方能访问对应租户的数据。 |
| `Authorization`    | 否     | 若通过服务网关转发，可视情况携带相关的 Bearer Token。                      |

### 4.2 请求参数 (Body - JSON)

| 参数名          | 类型     | 必填    | 默认值      | 描述                                                                                                    |
|:------------ |:------ |:----- |:-------- |:----------------------------------------------------------------------------------------------------- |
| `queryText`  | String | **是** | -        | 用户输入的搜索关键词或短句。                                                                                        |
| `pageNum`    | Number | 否     | `1`      | 当前请求页码，第一页从 `1` 开始。                                                                                   |
| `pageSize`   | Number | 否     | `10`     | 每页展示的最大条数。为保障性能，该值最大不可超过 `50`。                                                                        |
| `searchMode` | String | 否     | `hybrid` | 检索模式选型。<br>可选值：<br>`hybrid`: 【推荐】混合检索（语义+全文检索+智能重排）<br>`keyword`: 纯关键字检索（速度最快）<br>`semantic`: 纯语义向量检索 |
| `filters`    | Object | 否     | `{}`     | 过滤条件键值对。例如可传入 `{"data_source": "official_doc"}` 根据数据来源等元数据进行二级过滤。                                     |

### 4.3 请求示例 (cURL)

```bash
curl -X POST "http://<host>/api/v1/search" \
  -H "X-Search-AppCode: app_live_xyz123" \
  -H "Content-Type: application/json" \
  -d '{
        "queryText": "关于知识产权保护的最新通知",
        "pageNum": 1,
        "pageSize": 10,
        "searchMode": "hybrid",
        "filters": {}
      }'
```

### 4.4 响应参数说明

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "list": [
      {
        "doc_id": "dcf123_v1_fine_3",     // <--- 在此处获取该文档或该分片的唯一 ID，供下载接口使用
        "file_name": "高价值知识产权审查指南.pdf",
        "content": "此处为召回命中正文分片的内容摘要展示...",
        "_score": 0.892,
        "_source": {
            "metadata": {
                "source": "高价值知识产权审查指南.pdf",
                "publish_time": "2026-02-15"
            }
        }
      }
    ],
    "total": 45,             // 该查询命中的总数据条数（精排后）
    "pageNum": 1,            // 当前页码
    "pageSize": 10,          // 分页大小
    "hasMore": true,         // 是否还有下一页
    "took_ms": 132,          // 本次查询耗时（毫秒）
    "cache_hit": false,      // 是否命中全局缓存
    "sla_timeout": false     // 是否触发服务端超时保护（降级机制）
  }
}
```

## 5. 接口 3：原始文档下载/预览接口

当第三方业务系统通过**检索接口**获取到文档的分片摘录后，若需要获取源文件的完整物理文件提供给用户下载或在线预览，可用此接口将 `_id` 转换为具有时效性的临时访问 URL。

**请求路径**：`GET /api/v1/file/preview`
**Content-Type**：无需（Query 参数请求）

### 5.1 请求头 (Headers)

| Header名 | 必填 | 描述 |
|:---|:---:|:---|
| `X-Search-AppCode` | 否 | （如开启强网关认证可透传鉴权，默认该预览接口仅做参数签名/校验即可） |
| `Authorization` | 否 | 服务相关的 Bearer Token。 |

### 5.2 请求参数 (Query Params)

只需在 `docId` 或 `sourceName` 两者中提供**至少一个**即可（推荐通过 `docId` 以防止同名文件冲突）。

| 参数名       | 类型   | 必填  | 描述                                                                                                           |
|:----------|:-----|:----|:-------------------------------------------------------------------------------------------------------------|
| `docId`   | String| **推荐** | 搜索检索接口返回值中的 `_id` 字段（ES chunk doc_id）。系统会自动解析获得最精准的文档存储路径。             |
| `sourceName`| String| 选填   | 搜索检索接口返回值中的 `metadata.source` 或者文件名。若未查到 `docId` 可作为备选方式兜底查询其**最新版本**的地址。 |

### 5.3 请求示例 (cURL)

```bash
# 推荐使用 docId 的方式（假设搜索结果中查到的 _id 是 dcf123_v1_fine_3）
curl -X GET "http://<host>/api/v1/file/preview?docId=dcf123_v1_fine_3"
```

### 5.4 响应参数说明

接口获取成功后，将返回生成好的含过期时间的限时下载 URL。第三方系统可通过 `window.open(url)` 进行跳转预览，也可交由后端另存。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "url": "http://minio:9000/knowledge-base/2026/04/example.pdf?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Expires=900...", // 有效期 15 分钟的临时预签名直链
    "file_name": "example.pdf"
  }
}
```

异常情况示例：
```json
{
  "code": 404,
  "msg": "文件不存在或尚未入库，请确认文件名是否正确"
}
```
