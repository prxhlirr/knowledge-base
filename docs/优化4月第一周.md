# 政务知识库 RAG 系统 — 全链路优化文档

> **范围**：文档解析 → 分片 → 向量化 → 入库 → 检索
> **基准版本**：2026-03-29
> **原则**：所有方案均从第一性原理推导，拒绝补丁式修复

---

## 一、文档解析层（extract_text）

### D1｜LibreOffice 串行锁限制并发吞吐
- **根因**：`_doc_com_lock` 全局互斥锁将所有 .doc 解析串行化
- **影响**：`严重` — 批量导入吞吐量被锁死为单线程，10份文件需要顺序等待
- **方案**：引入进程池（`concurrent.futures.ProcessPoolExecutor`），每个子进程持有独立 soffice 实例，并发上限由 CPU 核数决定，彻底消除全局锁

### D2｜扫描件 PDF 内容为空
- **根因**：MarkItDown + pdfminer 只能提取文字 PDF；政府公文 PDF 大多数是扫描转换，为纯图片
- **影响**：`严重` — 所有扫描件文档入库后内容为空，等同于未导入
- **方案**：
  1. 在 PDF 解析路径中，先检测页面是否包含可提取文本（`pdfminer.pdfpage` 中 `page.chars` 是否为空）
  2. 若为图片页，调用 **PaddleOCR**（已在 Docker 环境，离线可用）进行 OCR 后再解析
  3. 结果写入 `metadata.is_ocr = true`，供后续质量审计使用

### D3｜表格内容静默丢失
- **根因**：python-docx P路只遍历 `doc.paragraphs`，`doc.tables` 中的表格被完全跳过
- **影响**：`高` — 行政许可收费标准、事项清单等表格型政务数据完全丢失
- **方案**：
```python
# 在 P路 python-docx 解析段落后，追加表格提取
for table in _p_doc.tables:
    for row in table.rows:
        row_text = " | ".join(cell.text.strip() for cell in row.cells if cell.text.strip())
        if row_text:
            _lines.append(row_text)  # 将表格行拼接为文本行，标记 chunk_type=table
```

### D4｜红头公文版头噪声进入语义空间
- **根因**：版头（发文字号、主送机关、附件标记等）与正文一视同仁，均进入向量化
- **影响**：`中` — 向量空间产生大量"XX市人民政府办公室文件"类无意义聚类中心
- **方案**：在 [_clean_raw_text()](file:///e:/project/AI/knowledge-base/ai_service/core/rag_pipeline.py#352-455) 中加入正则剥离：发文字号（`[〔\[\(].*?[〕\]\)]`）、主送机关（"（抄送：.*?）"）、附件标记行（"^附件[：:]?\s*\d+"）

### D5｜附件内容混入正文
- **根因**："附件一：xxx" 之后的内容与正文不加区分地分片和向量化
- **影响**：`中` — 附件向量干扰主文语义召回，且无法单独引用某附件内容
- **方案**：在分片前检测 "附件[一二三1-9]：" 出现的段落，将其后内容标记为独立文档单元

## 二、分片层（SemanticChunker）

### C1｜无 Word 标题样式的文档 section_path 全空
- **根因**：很多公文作者手动设置大号字体，未使用 Word 内置"标题"样式，P路无法通过 `paragraph.style.name` 识别
- **影响**：`高` — `section_path` 全为空，无法构建文档树，fine→coarse 回溯失效
- **方案**：在 P路解析后增加"字号+粗体"二次推断：若段落字号 ≥ 14pt 且全行字符数 < 30，认定为标题，按字号映射到 `#/##/###`

```python
# 补充：根据字号推断标题层级（Word run 级属性）
for _para in _p_doc.paragraphs:
    _sname = _para.style.name if _para.style else ""
    if not ("Heading" in _sname or "标题" in _sname):
        # 回退检测：最大字号 ≥ 14pt 且行长 < 30
        max_size = max((r.font.size or 0) for r in _para.runs) / 12700  # EMU→pt
        if max_size >= 14 and len(_txt) < 30:
            _lines.append(f"## {_txt}")  # 作为二级标题处理
            continue
    _lines.append(_txt)
```

### C2｜chunk_type 过于单一
- **根因**：所有分片统一标记 `chunk_type=body`，表格/列表/标题/注脚没有区分
- **影响**：`中` — 所有内容进同一向量化管线，目录、标题列表等低语义密度内容产生噪声
- **方案**：在 SemanticChunker 输出阶段，根据内容特征自动标注类型

| 规则 | chunk_type |
|---|---|
| 含 ` \| ` 符号的行（表格转文本） | [table](file:///e:/project/AI/knowledge-base/ai_service/core/chunking/semantic_chunker.py#213-222) |
| 全为 `第X条 …` 或 `X、…` 的列表 | [list](file:///e:/project/AI/knowledge-base/java_service/src/main/java/com/boyang/search/controller/DocImportController.java#248-274) |
| 长度 < 20 字符的标题行 | `heading` |
| 其他 | [body](file:///e:/project/AI/knowledge-base/ai_service/core/chunking/semantic_chunker.py#202-212) |

## 三、向量化层

### V1｜目录/标题列表进入向量空间
- **根因**：所有 `chunk_type` 一律送 BGE-M3 编码，包括"第一章….3页"这类纯目录内容
- **影响**：`中` — 向量空间产生无效聚类中心，轻微干扰 KNN 召回精度
- **方案**：在 [process_and_index()](file:///e:/project/AI/knowledge-base/ai_service/core/rag_pipeline.py#811-1220) 的向量化前置判断中，对 `chunk_type=heading` 且 `quality_score < 0.3` 的分片，**跳过 BGE 编码**，`vector` 写 `null`，仅依赖 BM25 倒排索引

### V2｜政务专业词向量表示精度不足
- **根因**：BGE-M3 是通用预训练模型，"行政复议""治安管理处罚"等术语与通用同义词难以区分
- **影响**：`低` — 当前环境能接受，GPU 就位后可改善
- **方案（长期）**：基于通用 BGE-M3 做政务语料 **继续预训练（Domain-Adaptive Pretraining）**，或微调一个政务专属 Embedding 模型，可在 GPU 就位后启动

## 四、HTML 文档融入

### H1｜缺少 HTML 解析能力
- **根因**：当前 [extract_text()](file:///e:/project/AI/knowledge-base/ai_service/core/rag_pipeline.py#456-809) 未处理 `.html/.htm` 文件类型
- **影响**：`高` — 政府网站公告/政策解读无法导入
- **方案**：在 [extract_text()](file:///e:/project/AI/knowledge-base/ai_service/core/rag_pipeline.py#456-809) 中添加 HTML 解析分支

```python
if local_path.lower().endswith((".html", ".htm")):
    from bs4 import BeautifulSoup
    with open(local_path, "rb") as f:
        raw = f.read()
    enc = chardet.detect(raw[:2000]).get("encoding") or "utf-8"
    soup = BeautifulSoup(raw.decode(enc, errors="replace"), "html.parser")
    # 剔除噪声标签（导航/页脚/脚本）
    for tag in soup(["nav", "footer", "header", "aside", "script", "style"]):
        tag.decompose()
    lines = []
    for el in soup.find_all(["h1","h2","h3","h4","p","li","td","th"]):
        txt = el.get_text(strip=True)
        if not txt: continue
        if el.name == "h1": lines.append(f"# {txt}")
        elif el.name == "h2": lines.append(f"## {txt}")
        elif el.name == "h3": lines.append(f"### {txt}")
        else: lines.append(txt)
    return "\n".join(lines)
```

### H2｜URL 来源追溯缺失
- **根因**：仅记录文件名，HTML 文档来源 URL 无法在结果卡片中展示
- **方案**：`metadata` 新增 `source_url` 字段；Java 端 [DocImportController](file:///e:/project/AI/knowledge-base/java_service/src/main/java/com/boyang/search/controller/DocImportController.java#24-596) 支持直接传入 URL 作为 `source_url` 参数，AI 服务下载后写入 metadata

## 五、检索层（SearchService）

### R1｜BM25 对多词专业术语召回率低
- **根因**：`minimum_should_match=50%` 配合 IK 分词器对长术语的切分，导致多词精确命中率不足
- **影响**：`高` — 搜索"行政许可机关受理期限"可能返回不相关结果
- **方案**：对 NAVIGATIONAL 意图查询（已实现旁路判断），ES BM25 改为 `minimum_should_match=1` 并添加 `boost` 权重优先完整短语匹配：
```java
q.bool(b -> b
    .should(s -> s.matchPhrase(m -> m.field("content").query(queryText).boost(3.0f)))  // 短语优先
    .should(s -> s.match(m -> m.field("content").query(queryText).minimumShouldMatch("1")))
    .minimumShouldMatch("1")
)
```

### R2｜BM25 / KNN 权重不随查询意图调整
- **根因**：`bm25Weight` / `vectorWeight` 全局固定，精确检索和语义检索使用相同权重
- **影响**：`中` — 精确关键词查询被 KNN 噪声干扰；语义问句被 BM25 的词频偏差拉偏
- **方案**：在 [hybridSearch](file:///e:/project/AI/knowledge-base/java_service/src/main/java/com/boyang/search/service/SearchService.java#401-2053) 中，根据 `navigationalBypass` 动态切换权重
```java
double bm25W = navigationalBypass ? 0.70 : bm25WeightVal;  // 精确检索：BM25 权重提升
double vecW  = navigationalBypass ? 0.30 : vectorWeightVal; // 语义检索：保持 KNN 主导
```

### R3｜KNN 候选集中 fine/coarse 双层重复加权
- **根因**：同一原文切成 fine 和 coarse 两层，两者都进入 KNN 候选池，fine→coarse 回溯后内容实际相同但优先级不同
- **影响**：`低` — 同文档结果排名虚高
- **方案**：fine→coarse 回溯完成后，对内容完全相同（MD5 相等）的候选去重，保留得分较高的一条

### R4｜缺少查询改写/扩展（Query Rewrite）
- **根因**：用户输入"公积金提取"，系统直接用此 3 字去做向量和 BM25，召回宽度受限
- **影响**：`中` — 长尾口语化查询命中率低
- **方案（中期）**：对 INFORMATIONAL 意图查询，调用本地轻量 LLM（如 Qwen-0.5B）做一次"查询改写"：输出 2-3 个同义扩展查询，并行召回后合并去重（Multi-Query Retrieval）
