# 文档相似度查找与原文预览接口规范

本文档旨在规范知识库编辑端及后台检索模块中涉及的“相似文档召回”与“原始文档浏览”核心 API。供前后端研发人员联调及后续维护查阅。

---

## 1. 文档相似度查找接口 (相似检测)

本接口供编辑工作台（Editor Workspace）实时或半实时调用。当用户输入或粘贴一段文本时，该接口通过 AI 向量化引擎配合 ES 混合检索框架，秒级反馈知识库中语义最相近的文档，防止文章撞车或辅助参考。

### 1.1 基础信息
* **接口路径**: `/api/v1/editor/similar-docs`
* **HTTP 请求方法**: `POST`
* **接口类型**: 语义检索 / 重排服务
* **安全策略**: 需于 Header 携带有效 `X-Search-AppCode` (租户标识) 或 JWT Token 用于权限鉴权。

### 1.2 请求头 (Headers)
| 参数名 | 类型 | 是否必填 | 描述 |
| :--- | :--- | :--- | :--- |
| Content-Type | String | 是 | 固定为 `application/json` |
| X-Search-AppCode | String | 否 | 租户 AppCode。若存在 JWT Token 则优先从 Claim 提取 |

### 1.3 请求体 (JSON)
| 字段名 | 类型 | 是否必填 | 默认值 | 示例值 | 描述 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **text** | String | **是** | 无 | "设立商事调解组织，应当符合..." | 待检测相似度的核心文本段落 |
| title | String | 否 | "" | "关于某地商事调解的管理条例草案" | 文本标题。系统会将 `title + "\n" + text` 合并处理 |
| topK | Integer | 否 | 5 | 3 | 最终召回的相似文档最大数量，取值范围：1 ~ 10 |
| excludeDocId | String | 否 | "" | "a4f1b2..._v3" | 排除匹配的文档ID（通常为当前正编辑文档） |
| excludeSource | String | 否 | "" | "草案初稿.docx" | 排除匹配的原始文件名 |

### 1.4 核心后端处理逻辑 (设计亮点)
1. **短文本预校验 (熔断机制)**: 
   - 当标准化处理后的文本长度低于设定下限（默认 80 字符）时，为了降低 GPU 推理负载，接口直接返回成功，但 `skipped: true` 且匹配列表为空。
2. **焦点窗口截取**: 
   - 内部将截取文本尾部最具信息密度的 **800 字符**（约 500 Token）用于精细计算，以保障时效性与规避 Rerank 模型 Token 溢出。
3. **Dense + Sparse 混合召回**:
   - 提取 BGE-M3 dense 与 sparse 向量，并由 ElasticSearch `knn` (余弦) 与 `rankFeature` (稀疏向量词频) 同步检索，确保兼具语义理解与关键字刚性匹配。
4. **严格数据隔离与权限过滤**:
   - ES 检索层会自动追加 `latest_version_filter`（只查文档最新版本）以及当前登录用户的权限筛选器（`deptCode`、`userId`）。
5. **跨片段聚合与 AI 重排 (Rerank)**:
   - 提取召回率最高的前 2 个片段聚合后，送入 AI 系统的 Rerank 重排接口算分。
   - 综合重排分（权重 85%）与向量分（权重 15%）计算出 `businessScore`，仅返回大于 **0.55** 阈值的文档。

### 1.5 响应体参数 (JSON)
#### 成功响应 (code: 200)
| 字段名 | 类型 | 描述 |
| :--- | :--- | :--- |
| code | Integer | 业务状态码，成功为 `200` |
| msg | String | 说明信息 |
| **data** | Object | 响应载荷 |
| data.total | Integer | 最终召回的匹配文档总数 |
| data.costMs | Long | 接口全流程总耗时 (毫秒) |
| data.queryChars | Integer | 规范化后的输入文本字符数 |
| data.cacheHit | Boolean | 是否命中 Redis 高速缓存 (60秒TTL) |
| data.skipped | Boolean | 是否触发了字数不足降级跳过（非必含，触发时为 true） |
| data.skipReason | String | 跳过的具体原因（如 `input_too_short`） |
| **data.items** | Array | 文档相似度排行列表，按 `similarity` 降序排列 |

#### items 数组内成员字段
| 字段名 | 类型 | 示例值 | 描述 |
| :--- | :--- | :--- | :--- |
| docId | String | "c6442d2fb_v1" | 在 ES 索引中聚合出的文档级全局 ID |
| source | String | "商事调节暂行法.pdf" | 原始存储文件名 |
| title | String | "关于促进商事调解机制发展的通知" | 文档的主标题（优先从元数据读取） |
| **similarity** | Double | 0.8234 | **综合加权重排得分** (0.00 ~ 1.00) |
| vectorScore | Double | 0.7811 | 向量引擎产出的粗排分 |
| rerankScore | Double | 0.8512 | 深度学习重排模型的绝对分值 |
| label | String | "high" / "near" | 相似度分级：`high` (>=0.85), `near` (>=0.70), `related` (>=0.55), `weak` (<0.55) |
| snippet | String | "本条例所称商事调解，是指..." | 文档最相近分片的内容摘要 |
| reason | String | "语义分析认为文章逻辑高度匹配..." | 系统推理出的匹配理由（调试用） |

#### data.timings (链路监控指标)
| 字段名 | 类型 | 描述 |
| :--- | :--- | :--- |
| vector_ms | Long | AI Service 提取 Dense & Sparse 向量耗时 |
| knn_ms | Long | ES 物理检索召回耗时 |
| rerank_ms | Long | AI Service 重排计算耗时 |
| candidate_count | Integer | 混合检索从 ES 召回的总候选分片数 |

## 2. 查看原文接口 (原始文档预览)

本接口主要面向客户端的“预览”功能。当用户点击搜索结果页面的“查看原文”或“在线阅览”按钮时，该接口负责解析文档定位信息，并向底层的对象存储服务（MinIO）申请限时的外部访问外链。

### 2.1 基础信息
* **接口路径**: `/api/v1/file/preview`
* **HTTP 请求方法**: `GET`
* **安全策略**: 匿名或具权限访问。接口内部会按业务逻辑根据入参反查库中的数据防跨越泄露。

### 2.2 请求查询参数 (Query Parameters)
> **注意**：`sourceName` 与 `docId` 二者**至少提供一个**。如果均提供，以 `docId` 优先解析。

| 参数名 | 类型 | 是否必填 | 示例值 | 描述 |
| :--- | :--- | :--- | :--- | :--- |
| **sourceName** | String | 否* | "商事调解条例.pdf" | 文件原始展示名（搜索结果中的 `file_name` 字段） |
| **docId** | String | 否* | "a2b3c4_v2_chunk_4" | 搜索命中分片在 ES 中的物理 `_id` |

### 2.3 核心后端解析流程
1. **精确定位 (通过 docId)**:
   - 系统提取 `docId` 并通过正则过滤掉分片后缀（如 `_chunk_3` 或 `_fine_12`），还原成文档的唯一版本标识 `{hash}_v{N}`。
   - 精准反查注册表（`kb_doc_registry`），以规避在不同单位上传重名文件导致的交叉引用错误。
2. **兜底模糊定位 (通过 sourceName)**:
   - 若 `docId` 缺省，使用 `sourceName` 字段在注册表中按创建时间降序排列，指向**最新版本 (findLatest)** 文档。
3. **MinIO 预签名下发**:
   - 校验 `storage_path` 非空。
   - 调用 Minio SDK 生成一个基于 **HTTP GET** 且有效期固定为 **15 分钟 (900秒)** 的预签名外链 URL，随后直接推给前端。
   - 前端拿到后通常采用 `window.open(url, '_blank')` 弹出新页面直接预览或触发浏览器自动下载行为。

### 2.4 响应体参数说明 (JSON)
#### 成功响应 (code: 200)
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| code | Integer | 成功固定为 `200` |
| msg | String | 提示信息："success" |
| **data** | Object | 数据载荷 |
| data.url | String | 最终有效的预签名外链。有效时限为 **15 分钟**。包含 Token、签名信息、失效时间戳 |
| data.file_name | String | 文件规范化展示名称 |

### 2.5 请求与响应示例
#### 场景 A：使用 docId 进行精确查找
* **GET 请求**: `/api/v1/file/preview?docId=9c4d0e0ff5_v2_chunk_11`
* **成功响应**:
```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "url": "http://minio-server:9000/knowledge-base/2026/05/9c4d0e0ff5_v2.pdf?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Expires=900&X-Amz-SignedHeaders=host...",
    "file_name": "深圳经济特区商事调解条例.pdf"
  }
}
```

#### 场景 B：使用文件名进行备用查找
* **GET 请求**: `/api/v1/file/preview?sourceName=深圳经济特区商事调解条例.pdf`
* **响应**: 与上述结构一致，默认召回该文件名的最新注册版本。

## 3. 全局错误状态码清单

在调用上述两个接口时，可能遇到以下非 200 类的业务及网络状态码，前端可针对性给以交互引导：

| HTTP Code | 适用场景 | 说明与引导建议 |
| :--- | :--- | :--- |
| **400** | 所有接口 | **参数格式错误**。入参格式不合法或必填字段缺失。例如 `/preview` 时未携带 docId 且未携带 sourceName |
| **401** | 相似度查找 | **租户未注册**。提供的 `AppCode` 无效或不在系统白名单内，拒绝提供推理算力资源 |
| **403** | 所有接口 | **无权操作**。安全层（`PermissionGuard`）拦截，当前登录的部门/人员账号没有该私有文档的可见性权限 |
| **404** | 原文预览 | **文件尚未入库**。`kb_doc_registry` 中查无此记录，或记录中的 `storage_path` 为空（原因可能是 Python-Java 异步回调失效，需引导用户重新上传） |
| **500** | 所有接口 | **系统内部异常**。后端抛错详情包含在 `msg` 中。通常发生于 AI 模型引擎宕机、ES 访问超时或 Java Heap 资源紧张等严重后端隐患 |
| **503** | 原文预览 | **文件存储服务不可用**。MinIO 处于宕机或降级部署模式下，导致预签名预授权握手失败 |
