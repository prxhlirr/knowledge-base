# 文档接入模块原子功能拆解

## 一、模块 1：历史文档批量导入

### 1.1 原子功能清单
| # | 原子功能 | 说明 | 输入 → 输出 |
|---|---------|------|------------|
| **C1** | 导入批次定义 | 创建导入 Batch ID, 关联现有系统文档列表, 初始化统计指标。 | 文档ID列表 → Batch 对象 |
| **C2** | 任务队列派发 (Task Dispatch) | 将 Batch 按 50 个文档为一个 Sub-Batch 切分, 存入待处理 Redis 队列。 | Batch → 多个任务片段 |
| **C3** | 并行执行器管理 | Java 层启动多线程/多容器, 监听队列并根据 AI 层压力控制消费速度。 | 任务片段 → 处理指令 |
| **D4** | 状态持久化与实时上报 | MySQL 记录每个 doc_id 的状态机：IDLE -> PENDING -> PARSING -> INDEXED -> ERROR | 处理信号 → 数据库更新 |
| **C4** | 错误重试决策 | 支持针对特定错误码（如 OCR/OOM/超时）自动或人工触发重新处理。 | 错误 Doc_ID → 重处理入队 |
| **C5** | 导入质量报告 | 生成批次看板：总数、成功率、耗时占比、高频失败原因汇总。 | Batch 执行记录 → 统计报表 |

### 1.2 处理流程
1. **预处理**：从现有库提取待更新文档 ID 列表；
2. **切片**：按固定大小切分为 Sub-Batches，写入消息队列；
3. **分发**：Java 消费队列，读取文件服务器原文并分发给 Python 文档解析微服务；
4. **解析与索引**：循环执行[解析-分片-向量化-索引]链路（详见相关模块文档）；
5. **持久化**：每成功一个文档，回写 ES 并更新 MySQL 状态标识，记录 TraceID。

## 二、模块 2：新文档自动触发增量向量化

### 2.1 原子功能清单
| # | 原子功能 | 说明 | 输入 → 输出 |
|---|---------|------|------------|
| **D1** | 业务事件订阅 (Event Hook) | 订阅现有公文系统“存档同步”消息，作为触发向量化的唯一入口。 | 系统事件 → 触发信号 |
| **D2** | Kafka 生产与背压控制 | 将新文档路径与元数据封装入 Kafka，防止 AI 服务过载时造成消息积压。 | 触发信号 → Kafka 消息 |
| **D3** | 任务排重与合并 | 针对短时间内重复修改同一文档的情况，进行任务归并，只保留最新版计算。 | Kafka 队列 → 唯一计算任务 |
| **D4** | 操作类型映射 | 将业务行为映射为 AI 动作：新建(Create) -> 新增索引；替换(Replace) -> 更新标记；删除(Delete) -> ES 删除。 | 动作类型 → 指令 |

### 2.2 实现技术
- **消息组件**：Kafka (Topic: `gov_doc_lifecycle`)
- **解耦方式**：现有系统发消息即返回成功，向量化结果在 ES 侧反映，实现检索最终一致性。

## 三、模块 3：Word / 文字版 PDF 解析适配

### 3.1 原子功能清单
| # | 原子功能 | 说明 | 核心技术 |
|---|---------|------|---------|
| **E1** | 文档头指纹验证 | 识别文件 Magic Number，拒绝损坏或伪造格式的文件（防止后缀名欺骗）。 | `python-magic` |
| **E2** | Word (.doc/docx) 结构解析 | 提取正文文本、标题层级样式、表格数据。 | `python-docx` / `antiword` |
| **E3** | 文本型 PDF 正文提取 | 提取 PDF 中可搜索的文本流，保留原始段落间距。 | `pdfplumber` / `pypdf` |
| **E4** | 编码自动适配与规范化 | 自动探测 GBK/UTF-8 并统一转码，过滤无法识别的二进制乱码。 | `chardet` |
| **E5** | 文档物理路径映射 | 将数据库中的相对路径映射为可访问的文件服务器/MinIO 地址。 | 系统配置 |

### 3.2 技术选型
- **底层引擎**：Python 解析库（在 Python 容器侧运行）。
- **优化**：对于超长 word (>100页)，采用流式读取，边解析边推送分片，不占用大块内存。

## 四、关键配置参数（最小粒度）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `import.batch_size` | 100 | 每次批量导入从 DB 捞取的文档数 |
| `worker.concurrency` | 20 | 并行解析文档的线程数 |
| `retry.max_attempts` | 3 | 单个文档解析失败后的自动重试次数 |
| `file.max_size_mb` | 50MB | 超过此大小的文档跳过全量解析，仅保留元数据 |
