智能政务向量检索知识库 & 搜索中台 - 最小粒度 PRD (V1.0)
====================================

核心原则
----

基于政务场景特性，聚焦 “数据准、切片准、检索准、运维稳、权限严”，补充现有方案缺失的多源接入、语义切片、版本管理、数据生命周期、用户反馈等核心能力，修复边界条件不闭环、粒度不足的缺陷，所有功能均拆解至原子级，可直接落地研发。

一、 多源数据接入与预处理层 (Multi-Source Ingestion & Pre-Processing)
--------------------------------------------------------

_研发关注点：多源兼容、防重防错、清洗闭环、政务格式适配_

表格

| ---------- | ---------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| **多源接入网关** | **A-01.1** | **文件指纹与防重入（全源适配）** | **逻辑：** 对文件上传 / URL 爬取 / DB 同步的数据源，统一计算内容哈希（文件：MD5/SHA256；URL/DB：内容 + 源标识哈希）。<br><br>**边界：** 哈希表查询，成功状态直接返回 Doc_ID；失败状态允许覆盖重试；DB 同步数据按 “主键 + 更新时间” 防重，避免重复拉取。<br><br>**防伪：** 文件读取 Magic Number + 政务格式验签（OFD 文件头验证），拒绝篡改后缀 / 伪造格式文件。                                                       | 返回`Doc_ID`/`Task_ID` + 处理状态（SUCCESS/FAILED/DUPLICATE） |

DB：单次增量同步数据量 > 10MB 则分批次拉取。<br><br>**边界：** 熔断后生成异步 Task_ID，支持前端查询进度。                                                                   | HTTP 413/415 报错 / 异步 Task_ID + 降级说明                   |
| **预处理流水线** | **A-02.1** | **政务文档格式差异化解析**    | **逻辑：** 按文档类型定制解析规则：<br><br>1. 版式 PDF/OFD：调用政务版式解析库，提取文本 + 坐标信息，保留段落结构；<br><br>2. 扫描件 / 图片：先 OCR 识别（优先政务 OCR 引擎），再校验识别准确率（<60% 则标记低质量）；<br><br>3. Word：提取正文（过滤修订记录 / 隐藏文本）；<br><br>**边界：** OCR 识别失败则打入死信队列，解析乱码（如编码错误）则尝试 GBK/UTF-8/GB2312 自动转码。                                          | 结构化文本`Parsed_Text` + 解析质量评分（0-100）                    |
| **预处理流水线** | **A-02.2** | **公文专项文本清洗**       | **逻辑：** 按政务场景清洗规则处理：<br><br>1. 固定清洗：移除页眉 / 页脚 / 页码、空白行、特殊符号（※/■等无意义符号）、重复换行；<br><br>2. 公文专属：移除 “仅供参考 / 内部传阅” 等标注、提取并保留公文标题 / 文号 / 签发机关（单独存入元数据）、清洗表格内无意义占位符；<br><br>3. 容错：清洗后文本为空则标记 “空文本”，仅保留元数据。                                                                                        | 清洗后纯文本`Clean_Text` + 清洗日志（清洗项列表）                      |
| **预处理流水线** | **A-02.3** | **死信队列闭环处理**       | **逻辑：** 定义死信队列入队规则：Sub-Task 超时（3min）、解析失败、OCR 准确率 < 60%、转码失败。<br><br>**边界：** 死信队列数据自动重试 2 次（间隔 10min），仍失败则触发人工介入（管控台弹窗 + 钉钉告警），人工标记 “放弃 / 重新解析” 后更新状态；死信数据保留 7 天，超时自动归档。                                                                                                                  | 死信队列`Dead_Letter_Queue` + 人工处理工单 + 最终状态更新             |
| **预处理流水线** | **A-02.4** | **文档解析状态机全闭环**     | **逻辑：** 状态树扩展：`INIT`→`INGESTION`→`PARSING`→`CLEANING`→`CHUNKING`→`EMBEDDING`→`INDEXING`<br><br>**终态：** `SUCCESS`（全流程成功）/`FAILED`（核心步骤失败）/`PARTIAL_SUCCESS`（部分清洗 / 解析失败）/`MANUAL_REVIEW`（需人工介入）<br><br>**边界：** 任意步骤失败均记录失败节点 + 原因，支持按 Doc_ID 回溯全流程日志。                                      | MySQL 全链路状态表（Doc_ID + 状态 + 失败节点 + 时间戳）                |

| ---------- | ---------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| **语义切片引擎** | **B-01.1** | **政务文档结构化语义切片**  | **逻辑：** 基于公文结构拆分 Chunk，优先级：<br><br>1. 公文层级：标题（一级 / 二级）→ 章节 → 段落 → 表格 / 图片说明；<br><br>2. 特殊结构：文号（独立 Chunk + 高权重）→ 正文 → 附件说明；<br><br>3. 切片尺寸：单 Chunk Token 数控制在 200-500 字（可配置），跨章节时优先截断在段落末尾。<br><br>**边界：** 无层级的纯文本采用滑动窗口（步长 100 字）切片，窗口重叠部分≥20 字保证语义连续。 | 语义化 Chunk 列表（`Chunk_ID`+`Chunk_Text`+`Chunk_Type`+`Parent_Chunk_ID`） |
